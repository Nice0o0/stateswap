# S₀ 算术实验（二）：边界修复后，相变消失了

> 接续 [state-arithmetic.md](state-arithmetic.md)（第一轮：尖锐相变）。
> 本轮在修复了训练管线的**字节级分词边界错位 bug** 之后重跑全部实验，
> 结论发生方向性反转：**S₀ 可以线性组合**——50/50 全局混合体同时保持
> 100% 猫娘风格与 100% 翻译能力。
>
> 原始数据：`docs/state_arithmetic2.json`；脚本：`scripts/state_arithmetic2.py`

## 1. 背景：边界错位 bug

第一轮实验的人格是用带 bug 的数据管线训练的：`build_example` 对"prompt+答案"
做**整句编码**，字节级词表的贪婪匹配产生跨边界合并 token，而 `prompt_len`
掩码按"单独编码的 prompt 长度"计算——掩码边界与 token 边界错位，答案首字符
被合并 token 吞掉一部分。修复：**prompt 与 completion 分段编码后拼接**，
边界 token 完整属于答案侧；serving 侧 prompt 同步加尾随空格与训练对齐。

修复的直接影响（mem-100 知识注入）：逐字召回 5% → 12%，泛化 2% → 12%。
更戏剧性的影响在算术实验——见下。

## 2. 重跑结果（边界修复后的 neko-1.5b / zh2en-1.5b，贪心解码）

| 混合方式 | 猫娘风格 | 翻译 |
|---|---|---|
| 全局 50/50 | **100%** | **100%** |
| 前 12 层猫娘 + 后 12 层翻译 | 83% | 100% |
| 后 12 层猫娘 + 前 12 层翻译 | 0% | 0% |
| 交替层 | 0% | 17% |
| S₀猫 − S₀译 | 100% | 0% |
| S₀译 − S₀猫 | 0% | 100% |

定性样例（全局 50/50 混合体）：

```
[闲聊] 早上好呀！今天想吃小鱼干吗？
       → 喵~今天想吃小鱼干吗？

[翻译] 今天的月亮又圆又亮。
       → Tonight's moon is round and bright.
```

同一个混合人格，闲聊时说猫娘中文、见陈述句就出英文——两个能力全强度共存。

## 3. 结论反转与解释

1. **第一轮的"尖锐相变"主要是边界污染训练的伪影。** 被 bug 污染的 S₀ 编码的
   是"残缺字节续写"这类表层模式，两个 S₀ 的表层模式互相冲突 → 全局混合时
   塌向单一模式。修复后 S₀ 编码的是行为级方向，可以线性叠加。
2. **逐层混合在修复后同样有效**（前半层猫娘 83% + 翻译 100%），且
   "front/back" 有不对称性：**前半层主导行为表达**（back_neko 全灭）——
   与状态在深层逐渐被 token 内容覆写的直觉一致。
3. **相似度地图**：neko↔zh2en 逐层余弦相似度仅 0.02–0.14（近正交），
   但修复后近正交方向依然可以线性叠加——"近正交但可组合"，与权重空间
   的 task-vector 合并现象形成有趣对照。

## 4. 方法论教训（对 state tuning 类工作的通用警告）

- **字节级分词 + 掩码边界错位**是 state tuning / 前缀类方法的高危陷阱：
  loss 可以完美归零（训练分布内完全拟合），但注入的是无法推理复用的
  碎片模式。必须用"逐字问题 + 换问法 + 换实体"三级探针交叉验证。
- **实验结论要随管线修复重测**：第一轮的相变结论在修复后反转。
  我们保留两轮数据（`state_arithmetic.json` / `state_arithmetic2.json`）
  作为方法论案例。

## 5. 未决问题

- sub_zh2en_minus_neko 出现退化输出（重复 token 循环）——减法几何仍不对称。
- back_neko 全灭的机理（深层覆写 vs 深层门控）未做归因。
- 混合体的双能力在更长对话 / 更难任务上是否保持，需要 StateBench 扩展评测。
