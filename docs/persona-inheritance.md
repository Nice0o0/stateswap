# S₀ 继承实验：训练式人格组合

> 研究问题：**能不能把一个已有人格的 S₀ 当"底子"，在上面训练出第二个能力，
> 同时保住第一个？**（"人格继承" / warm start）——这是 [state 算术](state-arithmetic.md)
> 留下的自然后续：混合是算术式组合，继承是训练式组合。
>
> 三臂对照 + 逐层解剖。原始数据 `docs/inheritance.json`，脚本
> `scripts/probe_inheritance.py`，分层训练 `--train-layers`（train.py）。

## 实验设计

底座 RWKV7-World-1.5B，数据 `zh2en_corpus_full.json`（7,369 对翻译），
2000 步 / ctx 512 / lr 1e-4 cosine / seed 42——三臂同数据同顺序，唯一变量是初始化：

| 臂 | 初始化 | 训练范围 |
|---|---|---|
| cold（对照） | S₀ = 0 | 全部 24 层 |
| warm（朴素继承） | S₀ ← neko-1.5b-mt（多轮猫娘） | 全部 24 层 |
| warm-front（分层继承） | S₀ ← neko-1.5b-mt | **只训 L00–07**，L08–23 冻结在供体值 |

L00–07 是[人格解剖](persona-anatomy.md)定位的"任务住址"（砍掉即翻译归零），
L16–23 是风格的主住址——分层继承 = 解剖指引的组合：任务写它的地址，别碰风格的地址。

## 结果

| 臂 | 翻译率（8 句裸中文→纯英文） | 猫娘风格命中（6 句闲聊） | 实际行为 |
|---|---|---|---|
| zh2en-1.5b（原版 4000 步） | 100% | — | 纯翻译器 |
| cold 2000 步 | 100% | — | 2000 步任务已饱和 |
| warm 朴素继承 | 100% | **0%** | **一切输入都被翻译成英文** |
| warm-front 分层继承 | 100% | **0%** | 同样一切输入都被翻译 |

朴素继承的定性回复（风格探针）：

```
[PROMPT] 早上好呀！今天想吃小鱼干吗？
[warm] 'Oh, good! Do you want some fish cakes today?'

[PROMPT] 陪我聊聊天吧，今天有点累
[warm] "Let's talk a bit today. I'm a bit tired today"
```

任务学习完全无损（100%），供体风格完全丢失（0%）——**zh2en 的"翻译一切"
任务吸引子接管了全部行为**，与 state 算术里"强任务模式胜出"是同一现象，
这次发生在训练式组合里。

## 机制线索：S₀ 几何与行为脱钩

逐层余弦（24 层按前/中/后 8 层聚合，原始逐层数据见 inheritance.json）：

| 对照组 | 前 L00-07 | 中 L08-15 | 后 L16-23 |
|---|---|---|---|
| cos(warm, donor neko) | 0.83 | 0.86 | 0.86 |
| cos(warm, cold zh2en) | 0.26 | 0.31 | 0.24 |
| cos(donor, cold)（参照） | 0.07 | 0.07 | 0.03 |

两个发现：

1. **行为翻转 ≠ S₀ 大幅旋转**：warm 与供体余弦仍高达 0.83–0.86（没有转向
   zh2en 方向，cold 与供体近正交），却发生了 0%→100% 的行为接管。
   少量状态偏移就足以把生成轨迹切换到任务吸引子——行为是**吸引子选择**，
   不随 S₀ 几何线性变化。这与 [state 算术](state-arithmetic.md)的
   "插值平滑、行为相变"互为印证。
2. **朴素继承的梯度动了所有层**（含风格的后层住址）——风格被冲不是
   "没保护"，而是全层训练默认会擦掉一切非任务内容。

## 分层继承：解剖指引的保护无效——风格内容完好，风格行为仍为 0

warm-front 只训 L00–07（全程 |S₀|∞ = 0.051 即供体水平；与供体逐层余弦
**中 8 层 = 1.000、后 8 层 = 1.000**——逐位未动，前 8 层 0.79 为任务偏移）。

结果：翻译 100%（只用前 8 层就完整学会了任务），风格 0%（与朴素继承一样，
一切输入都被翻译）。

```
[PROMPT] 早上好呀！今天想吃小鱼干吗？
[warm-front] 'Good! Today want to eat fish cake?'      ← 翻译，无任何猫娘痕迹
[供体 neko-1.5b-mt] '（蹭）喵呜~早呀主人！...'           ← 对照
```

**决定性发现：供体的风格内容被逐位完整保留在后 16 层，风格行为仍然是 0%。**

- [人格解剖](persona-anatomy.md)的"前半层主导行为表达"由此从相关性升级为
  因果性操纵：冻结后层（风格内容原封不动）→ 行为照样翻转。**行为模式由
  前层选择；后层的风格内容在前层被任务接管后不再被路由到输出。**
- "风格住在后层"（内容地址）是对的，"保护住址就保住行为"是错的——
  表达还需要前层的配合选择。
- 分层继承的真实价值因此改写：它是**把新能力精确写进指定层、其余状态逐位
  不动**的增量学习机制，而不是人格组合机制。

## 与 state 算术合起来看

| 组合方式 | 任务 | 风格 | 备注 |
|---|---|---|---|
| 算术混合 50/50（修复边界 bug 后） | 100% | 100% | state-arithmetic2 |
| 训练式组合（朴素全层） | 100% | 0% | 本实验 |
| 训练式组合（分层保护后 16 层） | 100% | 0% | 本实验，风格内容逐位完好仍不表达 |

两个方法不是竞争关系：**混合适合"已有人格的即席组合"（免训练、可保双能力），
继承适合"在既有底子上增量学新任务"（能真正学会新能力，但会覆盖行为模式）**——
混合不会产生新能力，继承会；继承不能保留旧行为，混合可以。

## 工程用法

```bash
# 人格继承：从已有 S₀ 热启动训新任务
python -m stateswap.train --model models/rwkv7-1.5b-world-hf \
    --data data/zh2en_corpus_full.json --out personas/zh2en-1.5b-warm \
    --init-from personas/neko-1.5b-mt/s0.pt --steps 2000 --lr 1e-4

# 分层继承：只训前 8 层（任务的住址），保护后层（风格的住址）
python -m stateswap.train --model models/rwkv7-1.5b-world-hf \
    --data data/zh2en_corpus_full.json --out personas/zh2en-1.5b-warm-front \
    --init-from personas/neko-1.5b-mt/s0.pt --train-layers 0:8 --steps 2000 --lr 1e-4
```
