# 长会话递归状态：范数轨迹与 SANE 的适用性诊断

> 研究问题：SANE（arXiv:2608.22354）报告 RWKV-7 在 **1 亿 token** 极长上下文下
> 出现「局部范数爆炸 atop 相对稀疏的基底」，因此在 chunk 边界做自适应 tanh 压缩。
> 本项目是否也需要这一层防护？
>
> 诊断思路：先测我们自己场景里的**范数轨迹**，再判断 SANE 是「需要接」还是
> 「只需引用对照」。
>
> 数据：`docs/longconv-norm-trace.json`（60 轮）；方法：每轮结束后读取
> 24 层 `recurrent_state` 的 Frobenius 范数。

## 结果

**1.5B / neko-1.5b，60 轮连续对话**（temp 0.7 / top_p 0.8 / rep 1.25 / ngram 8 /
退化护栏开启 / context_replay=0）：

| 指标 | 第 1 轮 | 第 60 轮 | 变化 |
|---|---|---|---|
| 逐层平均范数 | 28.84 | 34.74 | **×1.20** |
| 峰值（任意层） | 62.45 | 71.15（全程峰值 ≈70） | ×1.14 |
| 单层最大范数所在层 | L23 | L23（全程不变） | — |
| 退化轮数 | — | **0 / 60** | — |

轨迹形状：**单调但极缓慢**，前 10 轮涨得快（28.8 → 32.0），之后进入近对数式的
平台（32 → 34.7）。逐层看，增长集中在**浅层**（L0 ×1.60、L3 ×1.45），
最深层几乎不动（L21 ×1.09、L23 全程在 62–71 之间波动）。

**对照 S₀ 的量级**：人格初始状态 `|S₀|∞ ≈ 0.03–0.08`，而运行态范数是
**30–70**。也就是说，对话开始后状态幅度比初始状态大两到三个数量级——
S₀ 只负责偏置轨迹**起点**，不控制运行幅度（与 `docs/benchmarks.md` §7
「cos(状态, S₀) 两轮内 <0.05 而人格完好」一致）。

## 结论：本项目场景不需要 SANE 的数值防护

| | SANE 的场景 | 本项目场景 |
|---|---|---|
| 上下文长度 | **1 亿 token** | 60 轮 ≈ **2.8k token**（单会话，实测 2,776 token） |
| 失败模式 | 局部范数爆炸，推理分数崩塌 | 未见范数异常；60/60 轮无退化 |
| 幅度增长 | 溢出 | **×1.20**，且趋于平台 |
| SANE 的阈值 | α∈[3,5] 才能既稳又不掉分 | 阈值搬过来**没有依据**（我们的量级与尺度都不同） |

**所以：SANE 对本项目是「引用与对照」，不是「要接的实现」。**
在论文里恰当的位置是 §相关工作中的一句区分（「他们解决 1 亿 token 的数值
稳定性，我们解决每轮的内容毒化」），而不是一个新的实验小节。

**但要保留一个保留意见**：我们的最长会话只有 60 轮。SANE 的失败模式出现在
比这长四个数量级的上下文里。如果本项目以后要做「永不重启的长会话」
（例如 MemoPet 的连续陪伴 30 天），那时需要重新测——`docs/longconv-norm-trace.json`
的采集脚本可以直接复用。

## 附带发现：退化的机制不是范数

60 轮零退化，但 `docs/benchmarks.md` §7 记录的 15 轮探针里，单轮训练人格
在 T11–T14 出现连续 4 轮退化。两次的差别是**探针内容**：§7 的探针包含
「写 400 字故事」这类长生成请求，而本轮全部是短闲聊。

也就是说：**退化的触发因素是「长生成请求 + 内容脱轨」，不是「会话轮数」或
「状态幅度」。** 这与 §7 已经记录的反直觉结论一致（退化与 cos(state, S₀)
无关）——现在又多一条证据：它也与范数增长无关。

**两边的探针内容可以直接对照验证这一点**：
`scripts/probe_longconv.py` 的第 30–31 条 prompt 正是
「给我写一篇400字的小故事，关于一只猫探险的」与「这个故事的续集呢？再写400字」，
而 §7 记录的退化轮次 T11–T14 恰好紧邻这两条。本次 60 轮全程是 10 条短闲聊
循环（单条 max_new_tokens=96），零退化。**变量是生成长度，不是轮数。**

这也解释了为什么 60 轮平均 token 数前后持平（54.4 vs 56.8）：模型没有
「越聊越短」的趋势；§7 里出现的短回复是退化回滚后的表现，不是累积效应。

## 复现

```bash
# 60 轮范数轨迹（约 6 分钟，1.5B）
python -c "
import sys, torch; sys.path.insert(0,'src')
from stateswap.engine import Engine, _recurrent_4d
# ... 见 docs/longconv-norm-trace.json 的采集逻辑
"
```

脚本逻辑：注册人格 → 新建会话（context_replay=0）→ 循环 60 次
`eng.chat(...)` → 每轮后 `_recurrent_4d(cache[i]['recurrent_state']).norm()`
记录 24 层。
